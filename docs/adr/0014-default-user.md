# ADR-0014：先建一個預設使用者，使用者資料帶 userId

日期：2026-10-12
狀態：Accepted

## 背景

目前只有一個人在本機使用，沒有帳號系統（見 [願景](../vision.md)）。但之後可能開放多人，而 #42 已經把資料分成「共用的食材目錄」與「各自的購買紀錄」兩層。不確定是否真的會擴充。

## 決策

- 建立 `User` model，seed 時寫入一個預設使用者。
- 屬於使用者的資料（菜單、食譜，之後的購買紀錄）有 `userId`；食材目錄是共用的參考資料，沒有 `userId`。
- 程式透過 `getCurrentUserId()` 取得目前使用者，現在固定回傳預設使用者；寫入資料的 Server Action 要確認資料屬於目前使用者。
- 不做登入、權限與註冊。

## 考慮過的替代方案

- 不建 `User`，等真的要多人時再補：現在最簡單；之後補一個 migration 也不難，但每個查詢與 Server Action 都要回頭加條件，容易漏。
- 直接做帳號系統：目前沒有需求，是 [願景](../vision.md) 的非目標。

## 後果

- 每張使用者資料表多一個 `userId` 欄位，查詢要以它過濾。
- 之後要多人使用時，只需替換 `getCurrentUserId()` 並加上登入；共用食材目錄由誰編輯屆時另行決定。
