# ADR-0017：編輯卡是書架上的狀態機，以 pushState 同步網址

日期：2026-10-13
狀態：Accepted

## 背景

PLAN-006 的編輯介面是疊在書上的卡片：菜單編輯卡翻面成匯入卡，再換到食譜編輯卡，每一步都要有銜接動畫（翻面、收起、冒出）。同時希望網址反映目前的卡片，上一頁能退回、重新整理能回到同一張卡。書架本身有大量狀態（目前的書、每本書哪張紙在上、份數與勾選），不能因為編輯而重新掛載。

## 決策

- 編輯器是 `MenuShelf` 底下的一個元件與狀態機（`closed → menu ⇄ import → recipe`），所有卡片在同一個元件樹內，翻面與換卡由同一處控制動畫。
- 目前的卡片存在網址參數 `?edit=`（例如 `menu:<bookId>`、`recipe:<recipeId>`）。換卡時呼叫 `window.history.pushState`；狀態一律由 `useSearchParams` 讀出，Next 會把 `pushState` 與上一頁同步進 `useSearchParams`，不另外監聽 `popstate`。
- 不走 Next 的路由換頁，書架與首頁資料不會重新取得或重新掛載。
- 參數無效（格式錯誤、id 不存在或不屬於目前使用者）時忽略，只顯示書架。

## 考慮過的替代方案

- 攔截路由 + 平行路由（`@modal`、`(.)recipes/[id]/edit`）：網址是真正的路由，直接開網址會得到獨立頁面；但每張卡是不同的路由片段，換卡會重新掛載，翻面這類跨卡動畫要額外協調，三張卡的草稿狀態也要跨路由保存。
- 獨立編輯頁（`/recipes/[id]/edit`）：最簡單，但離開書架，無法有「從書上冒出」的轉場，也看不到背後的書。
- 只用元件狀態、不改網址：最簡單，但上一頁會直接離開首頁，重新整理也回不到編輯中的卡片。

## 後果

- 編輯中的草稿只在記憶體；重新整理會回到同一張卡，但未存的修改消失（防呆見 #56）。
- 讀網址參數的元件必須在 `<Suspense>` 內（首頁已有）。
- 之後若需要可分享、可直接開的編輯頁，再評估改為攔截路由。
