# ADR-0032：品項價格由食材成本即時計算，不存資料庫

日期：2026-10-16
狀態：Accepted

## 背景

PLAN-006 決定品項價格不手填，改由食材價格依用量加總算出，因此先把 `MenuItem.price` 改成選填。現在換算資料有了（ADR-0031），要決定算出來的價格放哪裡、算哪個量，以及資料不齊時怎麼辦。

## 決策

- 移除 `MenuItem.price`。每次讀取頁面時，用食譜用量和食材資料重新計算，不存結果。
- 菜單價格等於**每份**的食材成本（食譜沒寫份數時算整份）。食譜紙的營養也以每份顯示，不隨份數控制變動。
- 只計入有連到食材、而且有數量的用量；「適量」和沒連到食材的用量不計。
- 任何一行計入的用量算不出來（食材沒價格、缺換算數字），結果照樣顯示已算出的部分，並加上「不完整」的標記；完全算不出來就不顯示。

## 考慮過的替代方案

- 存檔時算好寫進 `MenuItem.price`：讀取比較快，但改了食材價格就要回頭更新所有用到它的品項，兩個地方的資料容易不一致。資料量小，即時計算的成本可以忽略。
- 保留手填價格，計算值只當參考：使用者選擇價格就等於成本加總。
- 有缺漏就完全不顯示：比較嚴謹，但目前大多數食材還沒有價格，菜單上幾乎看不到任何價格。

## 後果

- seed 的手填價格移除；菜單上的價格是成本，不是售價。
- 價格與營養的準確度取決於食材資料，計數單位的重量本來就是估計值。
- 之後要加「售價 = 成本 × 倍率」或手填覆蓋時，另立 ADR。
