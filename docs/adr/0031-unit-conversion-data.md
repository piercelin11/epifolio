# ADR-0031：單位換算用程式係數加上食材自己的重量與密度，資料庫保留原文單位

日期：2026-10-16
狀態：Accepted

## 背景

料理成本要算「價格 × 用量」，營養以每 100 g 計，兩者都要先把「2 瓣」「1 大匙」換成公克。通用單位（oz、cup）有固定係數；瓣、顆、把的重量因食材而異；體積換重量要知道密度（1 大匙油和 1 大匙麵粉不一樣重）。使用者之後也想依偏好切換顯示的單位。

## 決策

- 單位清單（`src/features/recipe/units.ts`，ADR-0016）的每個單位標記種類：重量（幾 g）、體積（幾 ml）或計數（因食材而異），係數只放在這份清單。
- 食材新增三項換算資料：預設單位、每個計數單位幾 g（JSON 物件）、密度（g/ml），另加 `unitsEstimated` 旗標，記錄這些數字是不是還沒人確認過的估計值。
- 價格拆成金額、數量、單位 id 三個欄位，例如 25 / 100 / `g`，讓價格也能套用同一套換算。
- 換算只在計算與顯示時進行，資料庫永遠存食譜原本的數量與單位。之後的單位偏好也只改顯示。
- 新食材的換算數字由匯入的 LLM 估計，現有食材由 Claude 一次估計寫入；使用者可以手動修改（介面見下方補充）。
- 只記一個價格，不做購買紀錄與平均價。

- 2026-10-16 補充：使用者決定食材卡片背面只編輯預設單位；密度與計數單位重量改在之後的食材列表頁編輯（#109），卡片存檔時原樣保留。

## 考慮過的替代方案

- 讓 LLM 在顯示或計算時換算：每次都花錢、結果不穩定，也無法離線計算。
- 匯入時把所有用量轉成公克存起來：計算變簡單，但會改動原食譜，「2 瓣蒜」變成「10 g 蒜」也比較不好用；來回換算還會累積誤差。
- 換算表另建一張資料表（食材 × 單位）：可以加索引與約束，但每個食材只有兩三筆，JSON 欄位與 `aliases` 的做法一致，也比較簡單。
- 用體積單位各自存重量（1 tbsp = 13.5 g）取代密度：比較直覺，但每種體積單位都要填一次；一個密度就涵蓋 tsp、tbsp、cup、ml、L。

## 後果

- 新增單位時要標記種類；計數單位還要考慮食材的重量資料。
- 換算資料缺漏時，成本與營養只能標示為不完整（ADR-0032）。
- 計數單位的重量本來就是估計值（一顆洋蔥大小不一），算出來的成本與營養都是概略值。
