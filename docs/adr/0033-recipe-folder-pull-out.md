# ADR-0033：食譜改成固定在畫面底部的資料夾，做法紙以滾動抽出

日期：2026-10-20
狀態：Accepted

## 背景

PLAN-011 把食譜紙改成資料夾：前層資料夾放名稱與用量，做法紙與營養卡從資料夾裡抽出。做法紙露出的高度跟隨內容、有上限；超過上限時，使用者希望滾動是「把紙繼續往上抽」，後面的菜單不動，而不是整疊紙一起捲動（ADR-0007 的做法）。資料夾高度要統一，用量太多也不能讓資料夾變高，否則會壓縮做法紙能露出的空間。

## 決策

- `PaperStack` 的 offset 不再放在捲動區裡，改成填滿書本的固定圖層；菜單紙照舊在捲動區捲動，食譜在上層時捲動區鎖住。
- 資料夾以下緣對齊畫面底部，高度是固定 token；做法紙以資料夾上緣為基準，用 transform 往上移，露出量 = min(內容高度, 上限) + 抽出量。
- 抽出量是 motion value，由自寫的 `useSheetPull` 接收滾輪、觸控拖曳與鍵盤，用 spring 平滑；換回菜單或收起做法紙時歸零。
- 抽紙時資料夾同步往下壓，壓到約一半高度後只剩紙往上抽；矮螢幕上做法紙因此能露出更多，又保留名稱與前幾行用量。被壓下時點資料夾（勾選框與 tab 除外）彈回。
- 用量固定三欄，群組接續排列、可跨欄；放不下時分頁（多欄容器左右平移），資料夾高度不變。

## 考慮過的替代方案

- 做法紙放在自己的原生捲動區（巢狀捲動）：有原生慣性與鍵盤支援，但捲動區要從資料夾下緣一路延伸到畫面頂端，資料夾以外的滾輪要轉送，紙下緣的裁切要靠 sticky 疊出來，層次（紙在後層資料夾之後、營養卡之前）難以維持。
- CSS scroll-driven animations：不用 JS，但 Firefox 預設不支援，而且抽出的上限要依內容高度決定。
- 資料夾跟著內容高度往上移（紙的上緣固定）：短食譜時資料夾位置不一，視窗矮時資料夾會掉到畫面外。
- 用量太多時資料夾變高、或在資料夾裡捲動：前者壓縮做法紙；後者的滾輪與抽紙衝突。
- 縮小資料夾：矮螢幕上做法紙多露出一些，但用量更容易分頁。
- 做法紙的放大按鈕（蓋過資料夾、可像菜單一樣捲動）：多一套捲動方式；有了下壓資料夾後先不做。

## 後果

- 食譜在上層時，滾動不再移動菜單紙；抽紙沒有原生捲動的慣性，手感由 `src/features/recipe/folder-motion.ts` 調整。
- 換紙動畫要分辨哪張紙隨捲動（菜單紙）、哪張固定（資料夾）。
- 食譜沒有自己的捲動區，食材卡片仍放在菜單紙的捲動內容中（ADR-0012），食譜在上層時捲動區不動，卡片位置照舊。
- 視窗太矮時做法紙的上限很小，主要靠抽出閱讀。
